### Добро пожаловать

Прежде всего, спасибо за желание помочь microwiki. В этом файле содержатся рекомендации и правила для участия в разработке проекта.

### Почему я должен следовать этим правилам

Эти правила позволяют сделать коммуникацию между разработчиками проще, а также позволяют:

- сделать проверку pull request быстрее и проще
- сохранить работоспособность старых функций при добавлении новых

### Какие виды вклада приветствуются

- предоставление отчетов об ошибках
- предложения о внедрении функции, которые сделают использование microwiki более удобным, быстрым и простым
- улучшение документации
- устранение ошибок и оптимизирование кода

# Базовые правила

### Ожидаемое поведение

- убедитесь, что код собирается и запускается на Windows и Linux без проблем с совместимостью
- убедитесь, что код проходит все базовые тесты без ошибок
- функции и классы, предназначенные для работы с конфигурациями, заголовками wiki, файлами и другими вспомогательными компонентами, следует размещать в `/src/microwiki/utils`, а не в `/src/microwiki/`

Добро пожаловать новенький, будь дружелюбным.

### Как сообщить об ошибке

Создайте issue с меткой `bug` и сообщите в нём следующую информацию:

1. Вашу ОС и версию
2. Описание бага
3. Шаги для воспроизведения ошибки
4. Версия Python, Textual и Rich, которые вы используете (заполняйте этот пункт только в том случае, если запускаете проект без сборки через `make run`)
5. Любые дополнительные примечание (если они есть) 

### Как отправить запрос на добавление функции

Создайте issue с меткой `enchancement` и напишите:

1. Описание функции
2. Почему ее следует добавить
3. Любые дополнительные примечание (если они есть) 

### Как создать pull request

Создайте pull request с меткой `enchancement` и напишите:

1. Улучшения/изменения сделанные в проекте
2. Почему это следует добавить
3. Сам код
4. Любые дополнительные примечание (если они есть) 

# Использование внутренних инструментов

### Задачи taskipy
Проект использует taskipy для автоматизации, ниже список задач taskipy для использования

`uv run task build` - собрать проект с помощью pyinstaller.

`uv run task lint` - проанализировать код с помощью ruff.

`uv run task lint_fix` - проанализировать код с помощью ruff и автоматически исправить ошибки.

`uv run task clean` - удалить директории ./dist и ./build.
